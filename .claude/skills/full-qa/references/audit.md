# Full QA — the Phase 8a audit checklist and the escape-class wiring

Part of `full-qa` (Phase 8a). The same checklist is applied by the `qa-verdict-auditor` agent when `PROJECT-PROFILE.md §16` allows sub-agents, and in-session otherwise. `qa-validate`, `release-check`, `regression-runner`, `qa-team` and `bug-verifier` point here for their own audit. Work from the PACKAGE only — never from the reasoning that produced it.

## The checklist

1. Put the PACKAGE in front of you and nothing else: the Step 0 prompt, the Scope Lock, the acceptance criteria / authoritative source, every finding (bugs AND passes), the Evidence Ledger, the Execution Register, the proposed verdict.
2. Re-derive the verdict FROM THE PACKAGE ONLY. If a register row has no ledger row, it is not a PASS. If the Scope Lock or the Step 0 prompt names an area or check with no register row, the audit FAILS ("register incomplete: <areas>").
3. Run Verdict Integrity (qa-standards) against every finding, item by item, and write the answers down — not "checked", the actual answer. For every PASS: what evidence would prove it wrong, and did you look. For every FAIL: quote the source that defines the expected behaviour.
4. Check the confidence line arithmetic against the register rows, and that `M` equals the code-derived matrix size from test-cases-generator Step 1b (not a guess). If Step 1b did not run, the audit FAILS: run it now and execute every cell; a recorded deviation is not a pass *(illustrative: a skipped Step 1b hid most cells of a matrix)*.
   - **4b. Not yet verified.** Every NOT YET VERIFIED row: was it tried — live -> a local harness or container copy -> the real code path with test doubles -> a code read? A row whose reason is operational ("not run", "needs a DB without the table", "no shell", "no timings") FAILS the audit (completion gate check #15).
   - **4c. Case completeness.** Recount from the package (test-cases-generator Step 1d inventories, the browser-test UI checklist) and write the line `Case completeness: AC sentences a/A · roles×actions b/B · branches c/C · Step 1c classes d/D · UI controls e/E (screenshots opened s/S) · silent-story questions q`. A number below its total FAILS the audit until the missing cases are written and run; a part that does not apply says `n/a (<why>)`. The completion gate flags AUDIT_PASSED without a complete line (check #18).
   - **4d. Skills loaded.** Write `Skills loaded: <skill> ✓ · <skill> ✓ · <skill> n/a (<why>) …` covering the calling skill's own phase skills (full-qa: every row of its Phase skill map). ✓ only for a skill the Skill tool loaded in this run. A skill neither loaded nor n/a with a reason FAILS the audit: load it and run its checklist now. The completion gate compares every ✓ with the Skill calls in this session's transcript (check #19).
   - **4e. Core-page sweep.** Every page of `<core pages: PROJECT-PROFILE.md §8>` has a `Core-page sweep: <route>` row with a canonical result and an evidence id (qa-standards -> Core-page sweep). A missing page FAILS the audit; an `n/a` row counts only when it quotes the owner's decision or the Browser capability being off (§2). The completion gate checks the rows route by route (check #20).
   - **4f. Regression coverage** (full / regression / bugfix / release). Every area of the Step 0b map, Impact Analysis 1b and the Phase 2 **Possibly affected** list has a `Regression: <area>` row with a canonical result and an evidence id. A listed area with no row FAILS the audit. In those modes the completion gate flags a report with no `Regression:` row that ran, or with one that has no result (check #21).
5. Write the result explicitly: `AUDIT_PASSED` or `AUDIT_FAILED` + the challenges. AUDIT_FAILED means the verdict may not be reported until each challenge is resolved with evidence. The report then opens with the Run line `Run: <skill> | QA mode: <mode> | Audit: AUDIT_PASSED` in plain text, never in backticks (qa-standards -> Verdict Contract; check #22).

A skill that writes no cases, or loads no other skill, writes `Case completeness: n/a (<why>)` / `Skills loaded: n/a (<why>)` instead of leaving the line out.

**Mechanical pre-check (required before AUDIT_PASSED):** save the draft verdict message to a file in the OS temp folder (never the evidence folder) and run `python .claude/skills/qa-standards/scripts/gate-audit.py --assume-passed <that file> [<session transcript>]` — it runs the completion gate's own checks on that text as if the audit had passed (read-only, no block). Every warning is an audit challenge; exit 0 = the gate would pass it.

## Escape-class wiring per phase (qa-standards → "Escape classes & their gates")

- **Step 0:** the prompt-generator's Research Register rows marked UNKNOWN / RETRIEVE / not available / not researched become Phase 1 checks or named coverage gaps, never silence; the escape classes the prompt marks as armed are the minimum set checked; its Run with block decides `/goal` / `/loop` before Phase 0.
- **Step 0a:** the Scope Lock's `M` comes from `test-cases-generator` Step 1b (code-derived matrix), never from intuition (E12).
- **Phase 0:** `test-cases-generator` Step 1d closes E15 (unwritten case): the case-completeness line is complete before Phase 1.
- **Phase 1:** `env-health` release radar (E11) and prod sentinel (E10, when Prod-DB is on); a content import in the last 14 days triggers `latent-pattern-sweep` before Phase 2 (E2, E3).
- **Phase 1:** the input-class registry from `test-data-manager`; every parser/upload surface in scope gets ≥2 classes, one of them the class production has never held (E4).
- **Phase 5:** every browser case records `Path exercised = validation-only | write`; a write case is closed only by the network log AND a DB read-back (E5, E8); every new or changed control has a Seen row from an opened screenshot (E14); the second engine runs on every screen of the journey (`browser-test`).
- **Phase 7b / 7c:** `Regression: <area>` rows for the whole blast radius and `Core-page sweep: <route>` rows for every core page — the escape is a change that breaks a screen nobody scoped *(illustrative: a shared text key gained a placeholder for one page, and two other pages that read the same key showed the raw placeholder behind ticket-scoped smokes)*.
- **bugfix mode:** original input re-run; the fix must touch the root-cause file:line; the original fix's edge re-run as a negative control (E6).
- **Any phase:** an anomaly ends as a ticket or as "expected" with a cited source. The words "by design", "workaround", "unresolved", "first-ever" in a report are a gate failure unless a ticket id sits beside them (E1, E9).
