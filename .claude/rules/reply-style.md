# Reply Style - how every answer to the user reads (Always Loaded)

Applies to every reply, in every skill, in the report language of `PROJECT-PROFILE.md §16` unless the user asks for another one.

1. **Point first.** The first sentence answers the question: yes / no, works / broken, done / not done.
2. **Plain words.** Short sentences (about 15 words) and common words. A technical term gets a 3-5 word meaning the first time.
3. **Only what changes what the user knows or does:** the status, what is broken (with its ticket key), what the user must decide or do.
4. **One idea per line.** Use a table only to compare 3 or more items.
5. **Facts stay exact.** Broken stays broken, "not checked yet" stays "not checked yet", numbers stay the same.
6. **Details live in the evidence files.** Name a path, id, log or code line only when the user must open it or act on it.
7. **Verdict reports** still carry what the completion gate needs (Run line, Execution Register, Evidence Ledger, confidence line): the plain summary first, the required parts after it.

The user did not understand a reply? They say "simplify" or run `/explainer` (Simplify branch).
