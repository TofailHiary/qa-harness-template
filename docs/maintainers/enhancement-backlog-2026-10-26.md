# Enhancement backlog — independent review, 2026-10-26

Produced with `docs/maintainers/external-review-prompt.md` against the tree at version 2.0.2 (the commit
that added `AGENTS.md`). Review only; nothing here is implemented. Line numbers refer to that tree.

## 1. Verdict on genericity and maturity

The template is generic: every tracked file is profile-driven, the validator proves it on each run and can
never leak the private list it checks against, and the installer, hooks, demo pipeline and clean-project
installs were executed rather than assumed. Maturity is solid at the method layer (shared vocabulary,
verdict contract, escape classes, independent audit) and uneven at the enforcement and automation layers.
The three biggest risks:

1. **Silent guard failure.** `.claude/settings.json:87-116` launch every guard with `python …`. On a machine
   where only `python3` exists (default macOS, many Linux images) the hook exits non-zero-non-2, which
   Claude Code treats as *non-blocking*: the harness looks installed and protects nothing. Nothing in
   `scripts/validate.py --installed` exercises a hook end to end.
2. **Verdicts are prose.** The Execution Register, Evidence Ledger and confidence line are free-text tables
   (`qa-standards/SKILL.md:420-460`). `completion-gate.py:101-125` and `qa-verdict-auditor` can only
   pattern-match them; neither can prove an evidence id points at a file or that `N of M` was counted.
3. **Textual tool rebinding.** `configure-project/SKILL.md:84-100` rebinds the DB tool by string replace
   across 36 skills; upgrades (`install.py` overwrites skills) silently undo it, and the prod tool and SQL
   dialect are not covered.

## 4. Do not do

- **Default the completion gate to enforcing.** Constraint 5 is served by honesty, not by blocking; the gate is heuristic and a false block costs trust (`docs/platforms-and-limitations.md` "heuristic"). Keep advisory by default; make enforcement a profile knob (already §16).
- **Let skills apply "trivial" fixes or commit on behalf of the user.** Constraint 2. The template documents bugs only.
- **Hard-code a Postgres/Mongo MCP package in `.mcp.json.template`.** Package names change and the engine is a project fact; keep the approval step in `configure-project` Step 5b (constraint 1 and 3).
- **Store secrets in `PROJECT-PROFILE.md` "for convenience".** Constraint 1 and the validator's credential rules.
- **Ship a `--runtime` that claims enforcement on runtimes without hooks.** Constraint 5; `AGENTS.md` already states what those runtimes lack.
- **Fold the private pattern list back into the repository "to make the scanner stronger".** Constraint 1; the self-check exists precisely so the scanner never carries what it protects against.
- **Replace the regex guards with a Docker sandbox requirement.** Constraint 3 (no global packages, Windows support).
